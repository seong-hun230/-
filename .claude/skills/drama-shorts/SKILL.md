# 드라마 쇼츠 제작

긴 영상(드라마 클립, 하이라이트, 본편)을 3분 이하 세로 쇼츠로 줄인다. 실제 편집은 `scripts/drama_shorts.py`가 하고, Claude는 **어느 구간을 살릴지** 정하는 편집자 역할을 한다.

`SKILL_DIR`은 이 SKILL.md가 있는 폴더의 절대 경로다.

## 0. 준비 확인

```bash
ffmpeg -version | head -1
python3 -c "import faster_whisper, scenedetect, cv2, yt_dlp, numpy; print('ok')"
```

없으면 설치한다: `pip install faster-whisper scenedetect opencv-python-headless "yt-dlp[default]" numpy` (ffmpeg는 시스템 설치). Windows에서는 `python3` 대신 `python`.

## 1. 입력 받기

- **영상 파일**: 경로를 그대로 쓴다.
- **유튜브 링크**: 스크립트가 yt-dlp로 내려받는다. 클라우드 서버에서는 유튜브가 "Sign in to confirm you're not a bot"으로 막는 일이 많다. 그 경우 우회하려 하지 말고, 사용자에게 (a) 영상 파일을 직접 주거나 (b) 자기 PC에서 `pc-video-tools/make-drama-shorts.bat`을 실행하라고 안내한다.
- 링크의 `&t=96s` 같은 시작 시각은 "이 지점이 중요하다"는 힌트로만 쓴다.

## 2. 분석

```bash
python3 "$SKILL_DIR/scripts/drama_shorts.py" analyze "<링크 또는 파일>" [--model small] [--lang ko]
```

작업 폴더(`<파일명>_shorts_work`)에 `analysis.md`(대사+시각+음량, 장면 전환 시각), `transcript.json`, `scenes.json`, `info.json`이 생긴다. 받아쓰기가 가장 오래 걸린다(CPU에서 원본 길이의 0.3~1배). 정확도가 필요하면 `--model medium`.

## 3. 편집 계획 세우기 (Claude가 직접)

`analysis.md`를 읽고 `plan.json`을 작업 폴더에 쓴다.

```json
{
  "title": "상단에 고정될 제목 (24자 이내, 2줄까지)",
  "clips": [
    {"start": 612.4, "end": 618.9, "why": "후킹: 가장 센 대사 미리보기"},
    {"start": 95.0, "end": 141.5, "why": "상황 설정"}
  ]
}
```

구성 원칙:

1. **후킹 (첫 3~8초)**: 가장 강한 한마디나 반전 직전 장면을 맨 앞에 미리 보여준다. 뒤에서 다시 나와도 된다.
2. **설정 → 갈등 → 절정** 순서로, 이야기 하나만 따라간다. 여러 줄거리를 섞지 않는다.
3. **끝은 궁금하게**: 결말 직전이나 여운이 남는 대사에서 끊는다.
4. 구간은 **대사가 끝나는 지점**에서 자르고, 가능하면 장면 전환 시각에 맞춘다. 대사 앞뒤로 0.2~0.4초 여유를 둔다.
5. 한 구간은 3초 이상, 구간 수는 5~15개가 적당하다. 인사·광고·예고·크레딧·의미 없는 침묵은 뺀다.
6. **총 길이 170~178초**를 목표로 한다. 178초를 넘는 부분은 스크립트가 잘라낸다. 원본이 그보다 짧으면 통째로 쓴다.
7. 제목은 내용을 과장하거나 영상에 없는 사실을 지어내지 않는다.

## 4. 렌더

```bash
python3 "$SKILL_DIR/scripts/drama_shorts.py" render "<작업 폴더>" --plan "<작업 폴더>/plan.json"
```

옵션:

- `--layout blur`(기본): 원본 전체를 가운데 두고 위아래는 흐린 배경. 제목은 위, 자막은 영상 아래.
- `--layout crop`: 가운데를 세로로 꽉 채움(좌우가 잘림). 인물이 가운데 있을 때만.
- `--no-subs`: 원본에 이미 자막이 박혀 있을 때.
- `--title "문구"`: 제목 덮어쓰기. `--title ""`이면 제목 없음.
- `--font "글꼴 이름"`: 기본은 Windows 맑은 고딕, Mac Apple SD Gothic Neo, Linux Noto Sans CJK KR. 리눅스에 한글 글꼴이 없으면 `fonts-nanum`을 설치하고 `--font NanumGothic`.

결과는 작업 폴더 옆에 생긴다: `<제목>_쇼츠.mp4`(1080x1920, 30fps), `<제목>_쇼츠.srt`, `<제목>_쇼츠_캡션.txt`.

## 5. 검수 후 전달

- 스크립트가 출력한 길이가 180초 미만인지 확인한다.
- 중간 프레임을 한두 장 뽑아 제목·자막이 영상이나 서로와 겹치지 않는지 본다: `ffmpeg -ss 30 -i 결과.mp4 -frames:v 1 check.jpg`
- 받아쓰기 오타(인물 이름, 고유명사)가 보이면 `transcript.json`을 고치고 `render`만 다시 돌린다. 분석 결과는 재사용된다.
- 사용자에게 mp4·srt·캡션 파일을 전달하고, 어떤 구간을 왜 골랐는지 3~5줄로 알려 준다.

## 빠른 길: 전부 자동

편집 판단 없이 한 번에 만들 때(사용자가 "그냥 자동으로"라고 하거나 PC에서 혼자 돌릴 때):

```bash
python3 "$SKILL_DIR/scripts/drama_shorts.py" auto "<링크 또는 파일>" [--title "제목"] [--target 175]
```

음량이 크고, 감정 단어·물음표·느낌표가 많고, 말이 빠른 대사 구간에 점수를 매겨 고른다. 줄거리를 이해하고 고르는 것이 아니므로 3번의 수동 계획보다 흐름이 거칠다. 사용자가 결과에 불만이면 `analysis.md`를 읽고 3~4번으로 다시 만든다.

## 주의

- 드라마·방송 영상은 저작권이 있다. 방송사 클립을 그대로 올리면 수익 창출 제한이나 삭제를 당할 수 있다는 점을 처음 한 번 알려 준다. 올릴지는 사용자가 정한다.
- 유튜브 쇼츠와 인스타 릴스는 3분(180초)까지다. 그보다 길게 만들어 달라는 요청이면 쇼츠로 분류되지 않는다고 알린다.
